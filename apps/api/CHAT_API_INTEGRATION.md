# Chat API — Integration Guide

> **Base path:** `/api/chat`
> **Auth:** Every endpoint requires a `Bearer` token in the `Authorization` header.

---

## Overview

The Chat API provides a persistent, AI-powered conversational assistant tailored for laboratory work. Conversations are organised into **sessions** — each session stores a full history of user and assistant messages in the database, giving the AI full context of everything said in that conversation.

### Two-mode architecture

| Mode | Endpoint | History | Use case |
|---|---|---|---|
| **Stateless** | `POST /api/chat` | None — each call is independent | Quick one-off queries from legacy clients |
| **Session-based** | `POST /api/chat/sessions/:id/messages` | Full history persisted in DB | Full chat UI with conversation threads |

> **Recommendation:** Use the session-based mode for all new integrations. The stateless endpoint is kept for backwards compatibility only.

---

## How sessions work

```
┌──────────────────────────────────────────────────────────────────┐
│                         Client (Frontend)                        │
└────────────┬─────────────────────────────────────────────────────┘
             │
             │  1. POST /api/chat/sessions          → create session
             │
             │  2. POST /api/chat/sessions/:id/messages
             │     Body: { content: "Why is my PCR showing bands at..." }
             │
             │     Server:
             │       a. Saves user message to DB
             │       b. Loads full message history
             │       c. Prepends system prompt
             │       d. Calls AI with complete context
             │       e. Saves AI reply to DB
             │       f. Auto-titles session from first message
             │       g. Returns { reply, session }
             │
             │  3. Repeat step 2 — context grows with every turn
             │
             │  4. GET  /api/chat/sessions           → list all threads
             │     GET  /api/chat/sessions/:id       → full thread + messages
             │     PATCH /api/chat/sessions/:id      → rename / pin to experiment
             │     DELETE /api/chat/sessions/:id     → delete thread + messages
             │     DELETE /api/chat/sessions/:id/messages → clear history only
             └──────────────────────────────────────────────────────┘
```

### Context pinning

A session can optionally be **pinned** to an `Experiment` or a `Protocol`. This is purely metadata — it lets the frontend display the session in context of a specific experiment page, and allows users to find their related conversations later.

```
POST /api/chat/sessions
{
  "title": "PCR troubleshooting",
  "experimentId": "e3b7c2a1-..."   ← pin to experiment
}
```

## Data Models

### ChatSession

```ts
interface ChatSession {
  id:           string;            // UUID
  userId:       string;            // UUID of the session owner
  title:        string;            // Display name (max 255 chars, default "New Chat")
  experimentId?: string;           // Optional — UUID of a pinned experiment
  protocolId?:  string;            // Optional — UUID of a pinned protocol
  createdAt:    string;            // ISO 8601
  updatedAt:    string;            // ISO 8601 — bumped on every new message

  // Relations (populated when fetched)
  user?:        User;
  experiment?:  Experiment;
  protocol?:    Protocol;
  messages?:    ChatSessionMessage[];
}
```

> `updatedAt` is bumped every time a message is added, so sorting sessions by `updatedAt` descending gives a "most recently active" order — the same behaviour as WhatsApp or iMessage.

### ChatSessionMessage

```ts
interface ChatSessionMessage {
  id:        string;              // UUID
  sessionId: string;              // UUID of the parent session
  role:      ChatMessageRole;     // "USER" | "ASSISTANT"
  content:   string;              // message text (max 32,000 chars)
  createdAt: string;              // ISO 8601
}
```

### ChatMessageRole enum

| Value | Description |
|---|---|
| `USER` | Message sent by the authenticated user |
| `ASSISTANT` | Reply generated by the AI |

> `SYSTEM` messages are **never stored** in the database. The system prompt ("You are the Lab Assistant AI…") is injected automatically on every AI call and is invisible to the client.

### Session Management

---

#### 1. Create a Session

Creates a new, empty chat session. The session title defaults to `"New Chat"` and is automatically updated to the first 60 characters of the user's first message when `sendMessage` is called.

```
POST /api/chat/sessions
Content-Type: application/json
Authorization: Bearer <token>
```

**Request body** _(all fields optional)_

| Field | Type | Description |
|---|---|---|
| `title` | `string` | Human-readable session name (max 255 chars). Auto-generated from first message if omitted. |
| `experimentId` | `string` | UUID of an experiment to pin this session to. |
| `protocolId` | `string` | UUID of a protocol to pin this session to. |

**Example — start a general chat**

```json
{}
```

**Example — start a session pinned to an experiment**

```json
{
  "title": "Western blot troubleshooting",
  "experimentId": "e3b7c2a1-1234-5678-abcd-000000000001"
}
```

**Response `201 Created`**

```json
{
  "success": true,
  "data": {
    "id": "s1a2b3c4-0000-0000-0000-000000000001",
    "userId": "u1b2c3d4-0000-0000-0000-000000000001",
    "title": "Western blot troubleshooting",
    "experimentId": "e3b7c2a1-1234-5678-abcd-000000000001",
    "protocolId": null,
    "createdAt": "2025-01-15T10:00:00.000Z",
    "updatedAt": "2025-01-15T10:00:00.000Z"
  },
  "message": "Chat session created successfully"
}
```

**Error responses**

| Status | `error` | Cause |
|---|---|---|
| `400` | `"Session title cannot be empty"` | `title` was explicitly set to an empty string |
| `400` | `"Session title must be less than 255 characters"` | Title too long |
| `401` | `"No token provided"` | Missing `Authorization` header |

#### 2. List Sessions

Returns all sessions belonging to the authenticated user, sorted by **most recently active** (`updatedAt` descending). Each session includes a **preview of the last message** — ideal for rendering a chat thread list.

```
GET /api/chat/sessions
Authorization: Bearer <token>
```

**Query parameters**

| Param | Type | Default | Description |
|---|---|---|---|
| `page` | `number` | `1` | Page number (1-based) |
| `limit` | `number` | `20` | Sessions per page |

**Example**

```
GET /api/chat/sessions?page=1&limit=20
```

**Response `200 OK`**

```json

  "data": {
    "data": [
      {

            "role": "ASSISTANT",
            "content": "There are several common causes for failed PCR amplification...",
```

#### 4. Update a Session

Rename a session, or change / remove its context pinning. Only the session owner may update.

```
PATCH /api/chat/sessions/:id
Content-Type: application/json
Authorization: Bearer <token>
```

**Request body** _(all fields optional)_

| Field | Type | Description |
|---|---|---|
| `title` | `string` | New session name (max 255 chars) |
| `experimentId` | `string \| null` | New experiment UUID, or `null` to unpin |
| `protocolId` | `string \| null` | New protocol UUID, or `null` to unpin |

**Example — rename only**

```json
{
  "title": "PCR band issues — run 3"
}
```

**Example — unpin experiment and pin to a protocol instead**

```json
{
  "experimentId": null,
  "protocolId": "p9f8e7d6-0000-0000-0000-000000000001"
}
```

**Response `200 OK`**

```json
{
  "success": true,
  "data": {
    "id": "s1a2b3c4-0000-0000-0000-000000000001",
    "title": "PCR band issues — run 3",
    "experimentId": null,
    "protocolId": "p9f8e7d6-0000-0000-0000-000000000001",
    "updatedAt": "2025-01-15T11:00:00.000Z"
  },
  "message": "Chat session updated successfully"
}
```

**Error responses**

| Status | `error` | Cause |
|---|---|---|
| `404` | `"Chat session not found"` | No session with that `id` |
| `403` | `"You do not have permission to modify this session"` | Session belongs to another user |
| `400` | `"Invalid request body"` | Malformed JSON |

```
Authorization: Bearer <token>
```

**Response `200 OK`**

```json

  "success": true,
  "data": null,
  "message": "Chat session deleted successfully"

```

**Error responses**

| Status | `error` | Cause |
|---|---|---|
| `404` | `"Chat session not found"` | No session with that `id` |
| `403` | `"You do not have permission to delete this session"` | Session belongs to another user |

### Messaging

---

#### 6. Send a Message

The core endpoint. Sends a user message, gets an AI reply, and persists both to the database.

**What the server does internally:**

1. Validates ownership of the session
2. Saves the user message to the DB
3. Loads the **full message history** from the DB
4. Prepends the system prompt (never stored, always injected fresh)
5. Sends the complete context to the AI
6. Saves the AI reply to the DB
7. If the session title is still `"New Chat"`, auto-titles it from the first 60 chars of this message
8. Bumps `session.updatedAt` so it sorts to the top of the list
9. Returns the AI reply + updated session metadata

```
POST /api/chat/sessions/:id/messages
Content-Type: application/json
Authorization: Bearer <token>
```

**Request body**

| Field | Type | Required | Description |
|---|---|---|---|
| `content` | `string` | ✅ | The user's message text. Max 32,000 characters. |

**Example**

```json
{
  "content": "My western blot is showing very high background noise. I used 5% milk blocking for 1 hour. What could be causing this?"
}
```

**Response `201 Created`**

```json
{
  "success": true,
  "data": {
    "reply": {
      "id": "m9z8y7x6-0000-0000-0000-000000000003",
      "sessionId": "s1a2b3c4-0000-0000-0000-000000000001",
      "role": "ASSISTANT",
      "content": "High background on western blots is a common issue. Based on your description, here are the most likely causes:\n\n1. **Antibody concentration too high** — try diluting your primary antibody further (e.g. 1:2000 instead of 1:1000).\n2. **Insufficient washing** — increase wash steps to 4–5 × 10 minutes with TBST.\n3. **Blocking time** — for some antibody/antigen combinations, BSA blocking works better than milk...",
      "createdAt": "2025-01-15T10:30:01.000Z"
    },
    "session": {
      "id": "s1a2b3c4-0000-0000-0000-000000000001",
      "title": "My western blot is showing very high backgro...",
      "updatedAt": "2025-01-15T10:30:01.000Z"
    }
  },
  "message": "Message sent successfully"
}
```

> **Auto-title behaviour:** If this is the **first message** in a session and the title is still `"New Chat"`, the server sets the title to the first 60 characters of `content` (truncated with `...` if longer). After that, the title is only changed when you explicitly call `PATCH /api/chat/sessions/:id`.

**Error responses**

| Status | `error` | Cause |
|---|---|---|
| `400` | `'"content" (string) is required'` | Missing or non-string body field |
| `400` | `"Message content cannot be empty"` | Empty string content |
| `400` | `"Message content must be less than 32,000 characters"` | Content too long |
| `404` | `"Chat session not found"` | No session with that `id` |
| `403` | `"You do not have permission to send messages to this session"` | Session belongs to another user |

### Legacy

---

#### 9. Stateless Chat (Legacy)

A single-turn chat call with no persistence. Messages are passed in the request and the response is returned directly — nothing is saved to the database.

```
POST /api/chat
Content-Type: application/json
Authorization: Bearer <token>
```

**Request body**

| Field | Type | Required | Description |
|---|---|---|---|
| `messages` | `ChatMessage[]` | ✅ | Array of messages to send to the AI |

**ChatMessage shape**

```ts
interface ChatMessage {
  role:    "user" | "assistant" | "system";
  content: string;
}
```

**Example**

```json
{
  "messages": [
    { "role": "user", "content": "What temperature should I use for PCR annealing?" }
  ]
}
```

**Response `200 OK`**

```json
{
  "success": true,
  "data": {
    "message": {
      "role": "assistant",
      "content": "The annealing temperature depends on your primer Tm. A general rule is Tm − 5°C..."
    }
  }
}
```

## Common Patterns

### Start a new conversation and send the first message

```ts
const API = 'https://api.example.com';
const headers = {
  'Authorization': `Bearer ${token}`,
  'Content-Type': 'application/json',
};

// 1. Create a session (body is optional — can send empty object)
const sessionRes = await fetch(`${API}/api/chat/sessions`, {
  method: 'POST',
  headers,
  body: JSON.stringify({}),
});
const { data: session } = await sessionRes.json();

// 2. Send a message
const msgRes = await fetch(`${API}/api/chat/sessions/${session.id}/messages`, {
  method: 'POST',
  headers,
  body: JSON.stringify({
    content: 'Why is my gel showing smearing instead of clean bands?',
  }),
});
const { data } = await msgRes.json();

console.log(data.reply.content);  // AI response
console.log(data.session.title);  // "Why is my gel showing smearing inst..."
```

### Load a chat screen

```ts
// Fetch the session with its full message history
const res = await fetch(`${API}/api/chat/sessions/${sessionId}`, {
  headers: { Authorization: `Bearer ${token}` },
});
const { data: session } = await res.json();

// session.messages is ordered oldest → newest, ready to render
const messages = session.messages; // ChatSessionMessage[]
```

### Render the sessions list (sidebar / drawer)

```ts
const res = await fetch(`${API}/api/chat/sessions?page=1&limit=20`, {
  headers: { Authorization: `Bearer ${token}` },
});
const { data } = await res.json();

// data.data is sorted by updatedAt DESC (most recently active first)
// Each session includes the last message for preview
data.data.forEach(session => {
  const preview = session.messages?.[0]?.content ?? 'No messages yet';
  console.log(`${session.title}: ${preview.slice(0, 60)}...`);
});
```

### Pin a chat to an experiment (e.g. from an experiment details screen)

```ts
// Create a session already pinned to the experiment the user is viewing
const res = await fetch(`${API}/api/chat/sessions`, {
  method: 'POST',
  headers,
  body: JSON.stringify({
    experimentId: currentExperimentId,
  }),
});
const { data: session } = await res.json();
```

### Implementing infinite scroll for messages

```ts
// On initial load, fetch page 1
const firstPage = await fetch(
  `${API}/api/chat/sessions/${sessionId}/messages?page=1&limit=50`,
  { headers }
);
const { data } = await firstPage.json();

// When user scrolls to top, fetch next page (older messages)
if (currentPage < data.totalPages) {
  const nextPage = await fetch(
    `${API}/api/chat/sessions/${sessionId}/messages?page=${currentPage + 1}&limit=50`,
    { headers }
  );
  // Prepend new messages to the top of the list
}
```

### React Native (Expo) — complete chat hook

```ts
import { useState, useCallback } from 'react';

interface Message {
  id: string;
  role: 'USER' | 'ASSISTANT';
  content: string;
  createdAt: string;
}

export function useChatSession(sessionId: string, token: string) {
  const [messages, setMessages] = useState<Message[]>([]);
  const [loading, setLoading] = useState(false);

  const sendMessage = useCallback(async (content: string) => {
    // Optimistically add user message
    const optimistic: Message = {
      id: Date.now().toString(),
      role: 'USER',
      content,
      createdAt: new Date().toISOString(),
    };
    setMessages(prev => [...prev, optimistic]);
    setLoading(true);

    try {
      const res = await fetch(
        `https://api.example.com/api/chat/sessions/${sessionId}/messages`,
        {
          method: 'POST',
          headers: {
            Authorization: `Bearer ${token}`,
            'Content-Type': 'application/json',
          },
          body: JSON.stringify({ content }),
        }
      );

      const { data } = await res.json();

      // Replace optimistic message + append AI reply
      setMessages(prev => [
        ...prev.slice(0, -1),
        { ...optimistic, id: data.reply.id }, // confirmed user message
        {
          id: data.reply.id,
          role: 'ASSISTANT',
          content: data.reply.content,
          createdAt: data.reply.createdAt,
        },
      ]);
    } finally {
      setLoading(false);
    }
  }, [sessionId, token]);

  return { messages, sendMessage, loading };
}
```

## Endpoint Summary

| Method | Path | Description |
|---|---|---|
| `POST` | `/api/chat` | **Legacy** — stateless single-turn chat |

## Notes & Constraints

| Constraint | Value |
|---|---|
| Max message length | 32,000 characters |
| Max session title length | 255 characters |
| Auto-title length | First 60 characters of the first message (truncated with `...`) |
| Default pagination — sessions list | 20 per page |
| Default pagination — messages | 50 per page |
| Message sort order | Oldest first (chronological) |
| Sessions sort order | Most recently updated first |
| System prompt | Injected server-side on every AI call, never stored |
| Session delete behaviour | Cascade — all messages deleted with the session |
| Clear history behaviour | Messages deleted, session kept, title reset to `"New Chat"` |
